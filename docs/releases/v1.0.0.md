# SwaDrive v1.0.0

## First Production Release

SwaDrive adalah private cloud yang dikelola sendiri untuk menyimpan dan
mengakses file melalui server Linux milik pengguna. Layanan file tidak dibuka
ke internet publik; akses production berlangsung melalui private network
Tailscale dan tetap dilindungi oleh autentikasi aplikasi SwaDrive.

Versi `v1.0.0` adalah baseline production pertama SwaDrive. Rilis ini menetapkan
backend Go yang telah dibekukan, metadata SQLite pada NVMe, content storage pada
HDD, serta operasi production melalui service `systemd` dengan Linux account
terbatas.

Fokus rilis ini adalah fondasi backend dan deployment yang aman serta dapat
dipulihkan. Flutter client untuk Android dan Linux sudah tersedia sebagai
scaffold project, tetapi belum menyediakan login, file browser, atau alur
transfer file untuk pengguna akhir.

## Highlights

- **Private Cloud** — Go HTTP API pada private tailnet tanpa public port
  forwarding untuk layanan file.
- **Authentication & Sessions** — Argon2id, opaque server-side sessions,
  logout, dan pencabutan session per perangkat.
- **File & Metadata Management** — list, metadata, search, folder creation,
  move, trash, restore, dan Range download melalui logical path tervalidasi.
- **Resumable Uploads** — fixed-chunk upload yang persisten, dapat dilanjutkan
  setelah request atau proses terputus, dengan pemeriksaan integritas.
- **Recovery Infrastructure** — transitional state, targeted startup
  reconciliation, explicit reindex, dan orphan-part cleanup yang diawali
  dry-run.
- **Audit Logging** — event keamanan dan administrasi append-only dengan
  akses API terbatas untuk owner.
- **Split Storage** — control/metadata plane pada NVMe dan file content pada
  HDD.
- **Production Boundary** — Tailscale, application authentication,
  restricted service account, storage identity validation, dan service
  `systemd`.

## Features

### Private Access

- Backend menyediakan Go HTTP API dengan prefix `/api/v1` pada port `8080`.
- Production access dibatasi ke private network Tailscale; application port
  tidak ditujukan untuk public internet exposure.
- Identitas perangkat/Tailscale, user aplikasi, administrator Linux, dan
  runtime service account dipisahkan.
- Health endpoint tersedia pada `GET /api/v1/health`; seluruh operasi user-byte
  memerlukan autentikasi aplikasi dan owner authorization.

### Authentication & Sessions

- Password disimpan sebagai Argon2id hash dalam format self-describing.
- Login menghasilkan opaque random bearer token 256-bit; server hanya menyimpan
  digest SHA-256 token tersebut.
- Session bersifat server-side, memiliki absolute expiry, dan dapat dicabut per
  perangkat. Logout hanya mencabut session aktif.
- Endpoint tersedia untuk melihat identity/session aktif, mendaftar session,
  dan mencabut session milik user yang sama.
- Login dilindungi oleh bounded request/Argon2 admission serta limiter berbasis
  username+peer dan peer-wide spray bucket.
- Tidak ada public self-registration; initial owner dibuat melalui local admin
  command.

### File & Metadata Management

- API owner-only untuk listing terpaginasikan, metadata lookup, filename/path
  search, pembuatan folder, move/rename, trash, trash listing, dan restore.
- Download berlangsung secara streaming dan mendukung HTTP Range.
- API menerima logical path, bukan physical host path. Absolute path, traversal,
  encoded traversal, null byte, dan symlink escape ditolak.
- Normal list, metadata, search, trash listing, dan upload status dilayani dari
  SQLite metadata index tanpa melakukan tree walk pada HDD.
- Metadata index menggunakan generation switch dan dapat dibangun ulang melalui
  explicit local-admin reindex.

### Resumable Upload

- Satu persistent upload session protocol digunakan untuk file kecil maupun
  besar.
- Fixed chunk berukuran 1, 2, 4, 8, atau 16 MiB, dengan default 4 MiB.
- Progress dan checksum setiap chunk disimpan di SQLite; retry chunk identik
  bersifat idempotent.
- Chunk ditulis streaming dengan bounded buffer dan bounded concurrency.
- Completion memverifikasi seluruh chunk, ukuran part file, serta optional
  whole-file SHA-256 sebelum publication.
- File dipublikasikan melalui same-filesystem atomic rename dan tidak menimpa
  destination yang sudah ada.
- Upload yang belum selesai memiliki expiry dan cleanup worker; status
  `finalizing` mendukung targeted recovery setelah restart.

### Trash & Reconciliation

- Normal removal memindahkan file atau directory tree ke trash dan
  mempertahankan original logical path untuk restore.
- Trash dan restore memakai transitional state agar known interrupted operation
  dapat direconcile saat startup tanpa general HDD scan.
- Interrupted metadata mutation yang tidak aman untuk dilanjutkan membuat index
  fail closed sampai administrator menjalankan reindex.
- Unknown upload parts dapat diperiksa menggunakan local-admin reconciliation
  yang bounded, age/name/type-gated, dan dry-run secara default; penghapusan
  memerlukan opsi `-apply` eksplisit.

### Audit

- Authentication, session, file, download, dan upload security/administrative
  events dicatat ke append-only SQLite audit log.
- Update dan delete terhadap audit events ditolak oleh database trigger.
- Owner dapat membaca event secara terpaginasikan dan memfilter event type,
  outcome, atau actor.
- Password, password hash, raw session token, file content, dan private physical
  path tidak dimasukkan ke operational log.

### Administration

Binary `swadrive-admin` menyediakan operasi lokal, bukan endpoint HTTP:

- `bootstrap-owner` untuk membuat initial owner dengan password interaktif;
- `reindex` untuk membangun generation metadata index baru; dan
- `reconcile-upload-parts` untuk meninjau dan, bila diminta secara eksplisit,
  membersihkan orphan upload parts yang memenuhi policy.

Server dan admin command menggunakan canonical database process lock. Backend
v1 mendukung satu process yang memiliki satu pasangan database/storage root.

### Storage Architecture

- SQLite menyimpan user/session state, audit, upload/trash operational state,
  serta derived file metadata index; file content tidak disimpan sebagai BLOB.
- `files/`, `uploads/`, dan `trash/` berada pada satu filesystem agar publication,
  trash, dan restore dapat memakai rename semantics yang sama.
- Storage identity marker diverifikasi sebelum content directories dibuka atau
  dibuat.
- Known inconsistency direconcile secara targeted atau dihentikan secara fail
  closed; startup dan normal browsing tidak melakukan full HDD scan.

### Production Deployment & Security

- Debian production server menjalankan backend sebagai service yang dikelola
  `systemd`.
- Runtime menggunakan restricted Linux account `personalcloud_service`,
  terpisah dari human administrator `admin_home_server`.
- Backend dikonfigurasi pada port `8080` dan dijangkau melalui Tailscale private
  network.
- Production storage root adalah `/srv/personalcloud`; database SQLite berada
  di `/var/lib/personalcloud/swadrive.db`.
- Storage identity marker production bernilai `swadrive-data-v1`.
- SwaDrive tetap storage fail-closed bila production storage mount tidak
  tersedia. Debian tetap diizinkan boot ketika HDD tidak tersedia, sementara
  backend tidak melayani data dari fallback directory.

## Platform / Technology

### Backend

- Go
- SQLite
- Linux/Debian
- Tailscale private network
- `systemd`

### Client

Repository memuat Flutter project dan runner/configuration untuk Android dan
Linux. Pada `v1.0.0`, client tersebut masih scaffold minimal dan belum
terintegrasi dengan authentication, file API, Range download, atau resumable
upload backend. Karena itu, rilis ini tidak mengklaim client file-manager yang
lengkap.

## Security Model

SwaDrive memakai defense in depth: Tailscale menjadi network boundary,
application authentication tetap diwajibkan, session disimpan server-side
sebagai digest opaque token, dan backend berjalan dengan restricted Linux
service account. Metadata/state pada NVMe dipisahkan dari file content pada HDD;
storage identity dan same-filesystem boundary diverifikasi sebelum layanan
berjalan.

Go app tidak melakukan TLS termination dan tidak menyediakan application-level
encryption at rest untuk file atau SQLite. Detail invariant, trust boundary,
dan limit tersedia pada [Security Model](../security-model.md).

## Production Storage Model

| Plane | Media/path production | Isi utama |
| --- | --- | --- |
| Control & metadata | NVMe — `/var/lib/personalcloud/swadrive.db` | Auth, sessions, audit, upload/trash state, file metadata index |
| Content | HDD — `/srv/personalcloud` | `files/`, partial `uploads/`, dan `trash/` |

Pemisahan ini menjaga normal metadata navigation tetap pada SQLite/NVMe. HDD
diakses ketika file bytes atau filesystem mutation memang diperlukan, serta
saat administrator menjalankan recovery/reindex eksplisit.

## Known Limitations

- Flutter client masih berupa scaffold; belum ada login, file browser, upload,
  download, trash, atau session-management UX.
- Backend v1 bersifat owner-only untuk file, upload, dan audit API, serta
  mendukung satu server process per database/storage-root pair.
- Tidak tersedia public sharing, multi-process storage ownership, content
  search, OCR, thumbnails, atau media indexing.
- File dan SQLite tidak dienkripsi oleh aplikasi. Go app juga tidak melakukan
  TLS termination; deployment mengandalkan private Tailscale path sebagai
  transport boundary.
- Audit events bersifat append-only dan terminal session/upload history belum
  memiliki automatic retention/archive command pada v1.
- Filesystem dan SQLite tidak memiliki cross-system transaction. Backend
  menggunakan compensation, targeted reconciliation, dan fail-closed metadata
  state, bukan mengklaim atomicity sempurna.
