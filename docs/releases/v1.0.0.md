# SwaDrive v1.0.0

## Rilis Production Pertama

SwaDrive adalah private cloud yang dikelola sendiri untuk menyimpan dan
mengakses file melalui server Linux milik pengguna. Layanan file tidak dibuka
ke internet publik; akses production berlangsung melalui jaringan privat
Tailscale dan tetap dilindungi oleh autentikasi aplikasi SwaDrive.

Versi `v1.0.0` adalah baseline production pertama SwaDrive. Rilis ini menetapkan
source code backend Go yang dibekukan untuk rilis ini, metadata SQLite pada NVMe,
isi file pada HDD, serta operasi production melalui service `systemd` dengan
service account terbatas di Linux.

Fokus rilis ini adalah fondasi backend dan deployment yang aman serta dapat
dipulihkan. Flutter client untuk Android dan Linux sudah tersedia sebagai
scaffold proyek, tetapi belum menyediakan login, file browser, atau alur
transfer file untuk pengguna akhir.

## Ringkasan Utama

- **Private cloud** — Go HTTP API pada tailnet privat tanpa public port
  forwarding untuk layanan file.
- **Autentikasi dan session** — Argon2id, server-side session berbasis opaque
  token, logout, dan pencabutan session per perangkat.
- **Pengelolaan file dan metadata** — listing, metadata, pencarian, pembuatan
  folder, move, trash, restore, dan download dengan Range melalui logical path
  yang tervalidasi.
- **Resumable upload** — transfer persisten berbasis fixed chunk yang dapat
  dilanjutkan setelah request atau proses terputus, dengan pemeriksaan
  integritas.
- **Infrastruktur recovery** — transitional state, targeted startup
  reconciliation, reindex eksplisit, dan cleanup orphan part yang diawali
  dengan dry-run.
- **Audit log** — event keamanan dan administrasi append-only dengan
  akses API terbatas untuk owner.
- **Pemisahan storage** — control/metadata plane pada NVMe dan isi file pada
  HDD.
- **Batas production** — Tailscale, autentikasi aplikasi, service account
  terbatas, validasi identitas storage, dan service `systemd`.

## Fitur

### Akses Privat

- Backend menyediakan Go HTTP API dengan prefix `/api/v1` pada port `8080`.
- Akses production dibatasi ke jaringan privat Tailscale; port aplikasi tidak
  ditujukan untuk eksposur internet publik.
- Identitas perangkat Tailscale, akun aplikasi SwaDrive, administrator Linux,
  dan runtime service account dipisahkan.
- Health endpoint tersedia pada `GET /api/v1/health`; seluruh operasi terhadap
  byte pengguna memerlukan autentikasi aplikasi dan otorisasi owner.

### Autentikasi dan Session

- Password disimpan sebagai hash Argon2id dalam format self-describing.
- Login menghasilkan opaque bearer token acak 256-bit; server hanya menyimpan
  digest SHA-256 dari token tersebut.
- Session bersifat server-side, memiliki masa berlaku absolut, dan dapat dicabut
  per perangkat. Logout hanya mencabut session aktif.
- Endpoint tersedia untuk melihat identitas dan session aktif, menampilkan
  daftar session, dan mencabut session milik pengguna yang sama.
- Login dilindungi oleh admission terbatas untuk request dan Argon2, serta
  limiter berbasis username+peer dan bucket spray peer-wide.
- Tidak ada self-registration publik; owner awal dibuat melalui command
  administrasi lokal.

### Pengelolaan File dan Metadata

- API khusus owner untuk listing dengan pagination, lookup metadata, pencarian
  nama atau path file, pembuatan folder, move/rename, trash, listing trash, dan
  restore.
- Download berlangsung secara streaming dan mendukung HTTP Range.
- API menerima logical path, bukan physical path pada host. Absolute path,
  traversal, encoded traversal, null byte, dan symlink escape ditolak.
- Listing normal, metadata, pencarian, listing trash, dan status upload dilayani
  dari metadata index SQLite tanpa melakukan tree walk pada HDD.
- Metadata index memakai generation switch dan dapat dibangun ulang melalui
  reindex eksplisit oleh administrator lokal.

### Resumable Upload

- Satu protocol resumable upload berbasis server-side session digunakan untuk
  file kecil maupun besar.
- Fixed chunk berukuran 1, 2, 4, 8, atau 16 MiB, dengan default 4 MiB.
- Progress dan checksum setiap chunk disimpan dalam SQLite; retry chunk identik
  bersifat idempotent.
- Chunk ditulis secara streaming dengan buffer dan concurrency terbatas.
- Finalisasi memverifikasi seluruh chunk, ukuran file `.part`, serta SHA-256
  keseluruhan file yang opsional sebelum publikasi.
- File dipublikasikan melalui rename atomik pada filesystem yang sama dan tidak
  menimpa file yang sudah ada pada path tujuan.
- Upload yang belum selesai memiliki masa berlaku dan cleanup worker; status
  `finalizing` mendukung targeted recovery setelah restart.

### Trash dan Reconciliation

- Penghapusan normal memindahkan file atau directory tree ke trash dan
  mempertahankan logical path asli untuk restore.
- Trash dan restore memakai transitional state agar operasi terputus yang sudah
  diketahui dapat ditangani melalui reconciliation saat startup tanpa scan HDD
  secara umum.
- Mutasi metadata yang terputus dan tidak aman untuk dilanjutkan membuat index
  fail-closed sampai administrator menjalankan reindex.
- Upload part yang tidak dikenal dapat diperiksa melalui reconciliation oleh
  administrator lokal. Operasi ini membatasi scan dan menerapkan filter umur,
  nama, serta tipe. Default-nya adalah dry-run; penghapusan memerlukan opsi
  `-apply` eksplisit.

### Audit

- Event keamanan dan administrasi untuk autentikasi, session, file, download,
  serta upload dicatat ke audit log SQLite yang append-only.
- Update dan delete terhadap audit event ditolak oleh trigger database.
- Owner dapat membaca event dengan pagination dan memfilter jenis event,
  outcome, atau actor.
- Password, hash password, raw session token, isi file, dan physical path
  internal tidak dimasukkan ke log operasional.

### Administrasi

Binary `swadrive-admin` menyediakan operasi lokal, bukan HTTP endpoint:

- `bootstrap-owner` untuk membuat owner awal dengan password interaktif;
- `reindex` untuk membangun generation metadata index baru; dan
- `reconcile-upload-parts` untuk meninjau dan, bila diminta secara eksplisit,
  membersihkan orphan upload part yang memenuhi kebijakan.

Server dan command administrasi lokal memakai process lock kanonis untuk
database. Backend `v1.0.0` mendukung satu proses yang memiliki satu pasangan
database dan storage root.

### Arsitektur Storage

- SQLite menyimpan state akun dan session, audit log, state operasional upload
  dan trash, serta derived metadata index untuk file; isi file tidak disimpan
  sebagai BLOB.
- `files/`, `uploads/`, dan `trash/` berada pada satu filesystem agar publikasi,
  trash, dan restore dapat memakai semantik rename yang sama.
- Marker identitas storage diverifikasi sebelum subdirectory penyimpanan dibuka
  atau dibuat.
- Inkonsistensi yang diketahui ditangani melalui targeted reconciliation atau
  dihentikan secara fail-closed; startup dan browsing normal tidak melakukan
  full HDD scan.

### Deployment dan Keamanan di Production

- Server Debian production menjalankan backend sebagai service yang dikelola
  `systemd`.
- Runtime menggunakan service account terbatas `personalcloud_service`,
  terpisah dari akun administrator `admin_home_server`.
- Backend dikonfigurasi pada port `8080` dan dijangkau melalui jaringan privat
  Tailscale.
- Production storage root adalah `/srv/personalcloud`; database SQLite berada
  di `/var/lib/personalcloud/swadrive.db`.
- Marker identitas storage di production bernilai `swadrive-data-v1`.
- SwaDrive tetap fail-closed terhadap storage ketika mount storage production
  tidak tersedia. Debian tetap diizinkan melakukan boot ketika HDD tidak
  tersedia, sedangkan backend tidak melayani data dari fallback directory.

## Platform dan Teknologi

### Backend

- Go
- SQLite
- Linux/Debian
- Jaringan privat Tailscale
- `systemd`

### Client

Repository memuat proyek Flutter beserta runner dan konfigurasi untuk Android
serta Linux. Pada `v1.0.0`, client tersebut masih berupa scaffold minimal dan
belum terintegrasi dengan autentikasi, File API, download dengan Range, atau
resumable upload pada backend. Karena itu, rilis ini tidak mengklaim client file
manager yang lengkap.

## Model Keamanan

SwaDrive memakai defense in depth: Tailscale menjadi batas jaringan,
autentikasi aplikasi tetap diwajibkan, session disimpan pada server sebagai
digest dari opaque token, dan backend berjalan dengan service account terbatas
di Linux. Metadata dan state pada NVMe dipisahkan dari isi file pada HDD;
identitas storage dan batas filesystem yang sama diverifikasi sebelum service
berjalan.

Aplikasi Go tidak melakukan terminasi TLS dan tidak menyediakan encryption at
rest pada level aplikasi untuk file atau SQLite. Detail invariant, trust
boundary, dan batas tersedia dalam [model keamanan](../security-model.md).

## Model Storage di Production

| Plane | Media dan path production | Isi utama |
| --- | --- | --- |
| Control & metadata | NVMe — `/var/lib/personalcloud/swadrive.db` | Autentikasi, session, audit log, state upload/trash, file metadata index |
| Content | HDD — `/srv/personalcloud` | `files/`, upload parsial dalam `uploads/`, dan `trash/` |

Pemisahan ini menjaga navigasi metadata normal tetap pada SQLite/NVMe. HDD
diakses ketika isi file atau mutasi filesystem memang diperlukan, serta saat
administrator menjalankan recovery atau reindex eksplisit.

## Keterbatasan yang Diketahui

- Flutter client masih berupa scaffold; belum ada login, file browser, upload,
  download, trash, atau session-management UX.
- API file, upload, dan audit pada `v1.0.0` hanya tersedia untuk owner, serta
  mendukung satu proses backend per pasangan database dan storage root.
- Tidak tersedia berbagi file secara publik, kepemilikan storage oleh beberapa
  proses, content search, OCR, thumbnail, atau media indexing.
- File dan SQLite tidak dienkripsi oleh aplikasi. Aplikasi Go juga tidak
  melakukan terminasi TLS; deployment mengandalkan jalur privat Tailscale
  sebagai batas transport.
- Audit event bersifat append-only, sedangkan riwayat session dan upload yang
  telah mencapai status terminal belum memiliki command untuk retention atau
  archive otomatis pada `v1.0.0`.
- Filesystem dan SQLite tidak dapat berbagi satu transaction. Backend
  memakai compensation, targeted reconciliation, dan state metadata yang
  fail-closed, bukan mengklaim atomicity sempurna.
