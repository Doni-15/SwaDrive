# SwaDrive v1.0.2

## Ringkasan

`v1.0.2` adalah patch yang mempertahankan kompatibilitas method/path/JSON API
untuk keamanan, konsistensi filesystem/metadata, resource timeout, credential
recovery, observability, CI, dan deployment Docker. Default konfigurasi listener
native berubah dan memerlukan perhatian saat upgrade. Client Flutter tetap
scaffold; tidak ada klaim bahwa UX login/file manager telah diimplementasikan.

## Perubahan Backend

- Menambahkan repair context bounded setelah side effect filesystem dan bounded
  context independen untuk marker fail-closed bila repair utama kedaluwarsa.
- Menambahkan metadata startup gate dan readiness endpoint.
- Menambahkan timeout server/JSON/chunk/download progress serta write budget
  khusus operasi upload.
- Menambahkan rehash stored chunk dan persisted whole SHA-256.
- Menambahkan reset credential owner lokal dan revoke-all session.
- Mengubah default listen address native menjadi loopback.
- Membatasi frekuensi storage probe pada health endpoint.

## Kontrak API

Perubahan bersifat additive atau failure-mode hardening:

- endpoint baru `GET /api/v1/ready`;
- endpoint metadata dapat mengembalikan HTTP 503 `metadata_unavailable` ketika
  startup reconciliation tertunda karena content storage tidak tersedia;
- upload yang completed selalu mengembalikan `whole_sha256` hasil server;
- request yang melewati deadline memakai HTTP 408 `request_timeout` bila response
  masih dapat dikirim; cancellation context memakai HTTP 408
  `request_cancelled`; JSON malformed tetap `invalid_json`.

Method, path, bearer header, JSON field yang sudah ada, fixed-chunk offset, dan
download Range tetap kompatibel. Scaffold Flutter belum memanggil API; kontrak
tersebut dicatat di `client/README.md` untuk implementasi berikutnya.

Kompatibilitas deployment berbeda dari kompatibilitas API. Default listener
native berubah dari `:8080` menjadi `127.0.0.1:8080`. Deployment native yang
sebelumnya mengandalkan default all-interface untuk direct Tailscale harus
menetapkan `SWADRIVE_LISTEN_ADDRESS='<tailscale-ip>:8080'` secara eksplisit.

## Docker dan CI

- `server/Dockerfile`: multi-stage, base image pinned digest, binary statis,
  runtime distroless non-root.
- `server/.dockerignore`: build context minimum dan tanpa test/build/secret.
- `compose.yaml`: bind mount persisten yang gagal cepat bila source belum ada,
  root filesystem read-only, drop capability, loopback publish, health check,
  dan graceful stop.
- `docs/deployment-docker.md`: persiapan ownership, build, networking,
  administration, backup, shutdown, dan update.
- `.github/workflows/ci.yml`: Go build/test/race/vet/format, Flutter
  format/analyze/test, serta Docker build dengan action pinned SHA.

## Versioning

Bump `v1.0.1` ke `v1.0.2` dipilih karena perubahan memperbaiki dan mengeraskan
behavior yang ada serta menambah opsi deployment. Method/path/JSON API tidak
breaking, tetapi secure listener default merupakan perubahan konfigurasi yang
didokumentasikan untuk upgrade native. Tidak ada fitur produk client yang
membenarkan minor/major bump.

Versi scaffold Flutter tetap `0.1.0+1`; ini adalah version scope aplikasi client
yang belum dirilis, bukan versi release backend/repository.

## Keterbatasan

- Tailscale ACL, firewall, unit systemd, ownership host, backup, dan production
  rollout aktual tidak dapat diverifikasi hanya dari repository.
- TLS aplikasi dan encryption at rest tidak ditambahkan.
- Per-peer connection quota, retention/archive, directory fsync, OpenAPI,
  signing/SBOM, serta backup automation tetap hardening lanjutan.
- Client Flutter belum memiliki API client, secure token storage, transfer,
  state machine, atau failure-state UX.
