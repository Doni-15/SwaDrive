# SwaDrive v1.0.1

## Ringkasan

`v1.0.1` adalah patch keandalan yang menjaga control plane dan HTTP API tetap
dapat dijangkau ketika content storage tidak dapat dibuka atau diverifikasi.
Operasi yang memerlukan HDD tetap fail-closed dan tidak pernah memakai
directory lokal di balik mount point sebagai fallback.

## Perubahan

- Backend memasuki degraded storage mode, bukan berhenti, jika volume content
  tidak tersedia saat startup.
- `GET /api/v1/health` melaporkan `status=ok, storage=available` atau
  `status=degraded, storage=unavailable` dengan HTTP 200.
- Operasi file dan upload yang memerlukan content storage mengembalikan HTTP
  503 dengan kode `storage_unavailable` dalam error envelope yang sudah ada.
- Login, `/auth/me`, pengelolaan session, dan API SQLite/NVMe lain yang aman
  tetap dapat bekerja ketika storage tidak tersedia.
- Provider storage mendeteksi kehilangan volume saat runtime sebelum operasi
  content berikutnya, menutup data plane, dan menjaga proses HTTP tetap
  berjalan.
- Validasi marker `.swadrive-volume`, directory wajib, persyaratan satu
  filesystem, logical path, dan containment `os.Root` tetap berlaku.

Error client-facing tetap memakai envelope dan request ID yang ada:

```json
{
  "error": {
    "code": "storage_unavailable",
    "message": "Server storage is currently unavailable.",
    "request_id": "..."
  }
}
```

## Dampak Kompatibilitas

- Perilaku API autentikasi dan session tetap kompatibel.
- Respons health memperoleh field `storage`; field `status` dapat bernilai
  `degraded` ketika proses sehat tetapi content storage tidak tersedia.
- Operasi yang membutuhkan content storage kini dapat mengembalikan HTTP 503
  `storage_unavailable`, alih-alih membuat seluruh backend tidak dapat
  dijangkau.
- `server_busy` tetap khusus untuk tekanan concurrency/resource dan tidak
  digunakan ketika storage tidak tersedia.

Kontrak pesan untuk client Flutter:

| Kondisi | Pesan client |
| --- | --- |
| Jaringan, Tailscale, atau API tidak dapat dijangkau | `Server tidak dapat dijangkau` |
| HTTP 503 + `storage_unavailable` | `Penyimpanan server tidak tersedia` |
| HTTP 503 + `server_busy` | `Server sedang sibuk` |

## Keterbatasan

`v1.0.1` tidak melakukan pemulihan otomatis di dalam proses. Setelah volume yang
benar kembali tersedia, backend tetap melaporkan storage tidak tersedia sampai
proses di-restart. Restart menjalankan ulang validasi identitas volume,
verifikasi directory dan satu filesystem, reconciliation trash/upload yang
sudah diketahui, serta pemeriksaan kesehatan metadata sebelum content access
dibuka kembali.

Operasi yang sudah berlangsung tepat ketika perangkat terputus tetap bergantung
pada error filesystem untuk berhenti. Provider menutup seluruh content access
berikutnya pada probe pertama yang gagal dan tidak pernah berpindah ke fallback
root.

## Upgrade

Repository tidak melacak unit `systemd`, sehingga tidak ada file unit yang
diubah dalam patch ini. Sebelum deployment, operator harus mengaudit unit aktual
dan menghapus dependensi wajib terhadap mount content jika dependensi tersebut
mencegah backend dimulai tanpa HDD. Urutan restart setelah storage kembali
harus tetap memberi kesempatan startup reconciliation berjalan.

Penyesuaian unit tidak boleh mengubah identitas runtime
`personalcloud_service`, memperluas privilege, mengurangi sandbox, membuka
firewall, atau mengubah batas Tailscale. Identifier di production tetap:

- storage root `/srv/personalcloud`;
- database `/var/lib/personalcloud/swadrive.db`; dan
- marker `swadrive-data-v1`.

Patch ini tidak melakukan perubahan otomatis pada server production. Build,
deployment, restart service, tag, dan publikasi rilis tetap merupakan tindakan
operator setelah review.
